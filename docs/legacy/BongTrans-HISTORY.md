# Decision log

Why each version is shaped the way it is. The changelog says what shipped. This file says what the next change should not undo. Update it in the same commit as a release. The procedure lives in [AGENTS.md](../AGENTS.md).

## 1.0.0

First Manifest V3 extension. The page is translated in place with the user's Gemini key because a hosted proxy would see shopping pages and the key. Text nodes are replaced through `nodeValue` so HTML, scripts, and form fields stay intact. Viewport-first batches exist because Taobao-style pages are too large to send at once. The cache key is source text plus target language plus model so a repeated badge does not call the API again. The default language is Korean and the prompt is tuned for Chinese shopping copy without being limited to that pair.

## 1.1.0

New Gemini keys got HTTP 404 for `gemini-2.5-flash-lite`, so that preset was removed. The default became `gemini-3.5-flash-lite`, with `gemini-3.1-flash-lite` as the other built-in. Overload (503/500) and a missing model (404) retry and then walk a fallback chain. An invalid key and a real quota error stay on that model and say the key is not the problem, because the earlier wording sent people to regenerate a valid key. The popup and the page note show the model that actually answered. The cache stores that model, so a later success on the primary model is a different entry. **키 확인** lists preset availability so overload is not reported as a bad key. **업데이트 확인** reads the GitHub release, which is why `https://api.github.com/*` is a host permission and why the zip name is part of the contract. A `v*` tag publishes the release so a manual zip is the fallback, not the normal path.

## 1.2.0

The success toast covered the page and did not help on a long scroll, so progress moved to a per-tab toolbar badge. The badge clears when translation is turned off or the address changes, and a red `!` is reserved for errors. The page error became a small corner note. A public manifest `key` pins the extension id so loading the folder from another path keeps `chrome.storage.local`. Settings export/import exists because deleting the extension, or moving to another profile, drops that storage. The file type stays `page-translator-settings` so the first export format still imports. The API key is inside the file on purpose. The UI tells the user not to share it.

## 1.3.0

Translate and Show original were two controls for one idea, and the second click was easy to miss. They became one ON/OFF switch. `Ctrl+Shift+Y`, `Alt+Shift+O`, and the context menu all toggle, matching the shortcuts people had already set. The badge behavior from 1.2.0 was left alone. An in-flight batch painted a shimmer underline on the parent element, not a wrapper, because a wrapper changes the DOM, retriggers the mutation observer, and shifts layout. Reduced motion kept a static underline. The fade was removed in 1.4.0 together with the underline. Cursor priority defaults off. Turning it on only reorders the queue that has not been sent. Pointer moves are sampled about every 150ms and element rectangles are cached until scroll or resize, so a large page does not call `getBoundingClientRect` on every mousemove.

## 1.3.1

The popup switch did nothing on a page that was already open. `enableInPage` called `topStatus`, a service-worker helper. `executeScript` serializes the function without closures, so the page threw `ReferenceError` before translation started. The popup treated that as `INJECT_FAILED` and drew the switch OFF. The injected functions are now self-contained and inline `window.top === window`. Frame 0 is injected first. Other frames are best-effort and cannot cancel the top frame. The popup locks the switch until the tab answers, because a 500ms status poll was racing the click back to OFF. A page that cannot be injected, such as `chrome://`, still returns OFF and shows the reason. The same release renamed the user-visible product to BongTrans. The manifest `key`, the repo name, the IndexedDB name, the settings file type, the CSS prefix, and the `package.json` name stayed, so existing installs and imports keep working. Release zips became `bongtrans-<version>.zip`. The update check prefers that name and still accepts `page-translator-*.zip`.

## 1.4.0

The cache had no age, no size, and no hit counters, so a long shopping session could only be wiped entirely. Values grew a `usedAt` and a byte estimate. The database moved to version 2 and old string values migrate in `onupgradeneeded`, stamped as used at that moment so the first prune does not delete them. Stats live in `cacheStats`, separate from settings: clearing translations must not erase the "how much did this save" number, and importing settings must not either. A mixed batch still spends one API call, so it counts saved strings only. A batch that never leaves the cache counts saved calls as well. Default cleanup is 90 days and no size cap. The size choices are presets so the options `<select>` always matches stored settings.

The underline could not show the original and the translation at the same time. The new reveal writes the translation immediately, then covers the element with a fixed overlay of the original text and clips that overlay away over 560ms. The overlay is not a wrapper around the text node. It is skipped by the walker (`translate="no"` and `pt-page-translator-sweep`). Direction follows the element's computed direction so RTL scans from the inline-start side. Reduced motion is a crossfade, not a sweep. Hundreds of nodes do not each run an infinite animation: the glowing pending style and the scan are capped at eight, with a short queue for scans. Text outside that cap still updates. The animation defaults on because it is the feedback that replaced the underline, and **번역 등장 애니메이션** turns it off. The preference travels through `contentPrefs` with cursor priority, and that object is still the only prefs payload, so the API key cannot ride along.

`AGENTS.md`, `CLAUDE.md`, `.cursor/rules/agents.mdc`, and this file were added so the next agent can continue from the repo URL without the chat transcript. They are not in the release zip. The zip list is still the extension itself.

## 1.4.1

A real Chrome session on Taobao showed the scan line away from the text that was changing. 1.4.0 wrote `nodeValue` as soon as the translation arrived, then started two independent CSS animations on the parent element's `getBoundingClientRect`. The box included padding and siblings, so a wrapped paragraph and an inline span did not move the edge along the glyphs. Scroll left that fixed box where it was first measured. The scan queue and the 50ms stagger ran after the text had already swapped, so a node waiting for a slot looked translated with no scan, or scanned a string that was already the translation. The original string now stays until that node's scan starts. Each line is a `Range` client rect. `--pt-reveal` is one Web Animations timeline from 0 to 1 over 560ms, and every line's clip and scan read `--pt-p` derived from it. Eight scans run at once. The rest keep the original text and the pending glow, with no stagger and no queue cap. Scroll remeasures while the original is still in the node. Reduced motion and the animation-off setting still write immediately.

The same release follows the repository rename from `Baegovda/page-translator` to `Baegovda/bongtrans`. The update check calls `https://api.github.com/repos/Baegovda/bongtrans/releases/latest`. GitHub redirects the old URL, but the extension does not rely on that. The extension id, IndexedDB name, settings file type, CSS prefix, `package.json` name, and `bongtrans-<version>.zip` asset name stay, so existing installs and older zips still match. The release workflow sets `GH_REPO` to `Baegovda/bongtrans`.

## 1.5.1

A dense Taobao page (~450 text nodes, dark theme) showed the 1.4.1 scan as a flicker, not a wipe. Three things stacked. Only `MAX_SWEEPS` (8) overlays ran, so cells changed in groups about 560ms apart. Each cell binary-searched line boxes with `getClientRects` and inserted a measuring probe between those reads, so layout and paint interleaved. The original glyphs were hidden with `webkitTextFillColor` and a sampled background, then the overlay was removed and `nodeValue` was written at the end of that cell's own clock. On a dark page the fill and the background did not match, so the cell popped empty and back. A longer Korean string then reflowed icon labels while neighboring scans were still moving. Reduced motion hid the overlay with `display: none`.

1.5.1 uses one vertical wiper for the whole batch. `requestAnimationFrame` reads every text rect first (`getBoundingClientRect` once, not per glyph) and only then writes fixed overlays. The line moves with `transform: translate3d`. Each cell's original and translation sit in that overlay and cross with `clip-path` on `--pt-p`, which is derived from the same clock (`planWiperOrder` / `crossProgress`), so the clip cannot get ahead of the line. `will-change` is set on the line and on a cell only while its clip is between 0 and 1. The live `nodeValue` stays put until the pass ends, then every cell is written in one turn and the overlays come off. That is the layout change, and it happens after the wipe. A chunk that arrives after the line has passed its row uses the same clip on a short clock (`SOFT_MS`) instead of appearing at full opacity. Turning translation off, or **원문 보기**, runs the wiper upward. `prefers-reduced-motion` and **번역 등장 애니메이션** off still write immediately and do not fade the cell. Text-only elements use `-webkit-text-fill-color: transparent` while the overlay is up so the original does not ghost through it; elements that also contain icons are not held, because a fill on the parent would blank the icon. The animated pending glow stays capped at 8. The sweep count cap is gone.

The mutation observer delivers records after the write stack, so a lock around `nodeValue` is not enough by itself. Overlay roots are skipped by the `pt-page-translator-sweep` / `pt-page-translator-wiper` class, and our text writes still go through `expectedWrite`. Do not wrap the text node, do not toggle `display` or `visibility` on it, and do not animate `font-size` or width.

## 1.5.0

BongChzzk 1.4.0 through 1.5.1 grew a one-click updater for an unpacked folder. BongTrans already had the release workflow, `lib/updates.js`, and a manual zip link. This release takes the behavior that survived BongChzzk's real failure (a write that stopped halfway and left the folder unloadable) and fits it to this repo.

The failure there was Chrome reloading the unpacked extension when `manifest.json` changed, which closed the update tab before the rest of the files landed. Every error was also shown as a cancelled folder picker. The fix is the same shape: save the extracted files to IndexedDB before touching disk, skip bytes that already match, write at most six files at once, write `manifest.json` last, and offer **이어서 완료** when the saved version is still newer than the running one. The first six paths are fixed (`update.html`, `update.js`, `update.css`, then the three modules that page imports) so zip entry order cannot push the updater out of that first batch. Popup files live under `popup/` here, not next to `manifest.json`, so the early list uses those paths.

The directory handle is not stored in the translation database. That database stays `page-translator`. A second database, `bongtrans-install`, holds `kv` (the handle) and `pending` (the interrupted zip). **번역 캐시 지우기** therefore cannot forget the folder. The picked folder and the downloaded manifest must both be `name: "BongTrans"` and must carry this extension's public `key`. A same-named copy with a different key would be a different extension id, and writing into it would not update the running one.

`zipUrl` still falls back to the release HTML page when GitHub has no zip asset, because the manual **zip 다운로드** button did that already. The installer must not fetch that URL. `assetUrl` is the `browser_download_url` or null, and **지금 업데이트** is hidden when it is null. The download follows a redirect from `github.com` to `objects.githubusercontent.com` or `release-assets.githubusercontent.com`, so those three hosts are permissions. They are not `<all_urls>`. The page text and the Gemini key are still not sent.

The release workflow already matched BongChzzk's test, version check, changelog extract, and `gh release create` steps. The gap was the zip check added after BongChzzk shipped a release missing content scripts. `scripts/verify-release-zip.js` is ESM, because `package.json` is `"type": "module"` and `require()` in the workflow is the mistake `AGENTS.md` already forbids. It reads manifest paths (service worker, popup, options page, icons) plus the updater files and `content/content.js`, which is injected by name and is not a `content_scripts` entry. It also rejects a zip that picked up `test/`, `scripts/`, or `package.json`.

Removed files are left in the folder. There is no delete pass. 1.5.0 cannot update itself from 1.4.2; the button ships in 1.5.0, so the first install is still **Load unpacked**. A full Chrome run of the picker, the permission, and the reload was not done for this change. `chrome.runtime.reload()` in headless Chrome for Testing can unload the extension instead of restarting it, so that environment cannot prove the last step.

## 1.4.2

A bot that cloned `https://github.com/Baegovda/bongtrans` and read only the 1.4.0 handoff still had to rediscover which tools exist and how Chrome for Testing is launched. The handoff now starts with BOOTSTRAP: read the kit, run `scripts/bootstrap.sh`, install any required MCP it marks missing, then ship on `main`. The script only checks and tests. It does not pull images or write tokens, so a missing Docker daemon cannot mutate the machine or fail the test run.

GitHub MCP is the official `ghcr.io/github/github-mcp-server` image, not the retired npm package. The token stays in `GITHUB_PERSONAL_ACCESS_TOKEN`. Cursor expands `${env:NAME}`; Claude Code expands `${NAME}`. `gh` remains the fallback so a release is not blocked when the MCP server cannot start. Playwright MCP is for ordinary browsing and does not load this unpacked extension. Extension checks stay on Chrome for Testing plus `chrome-devtools-mcp --browser-url`. A filesystem MCP is omitted on purpose: the checkout is already the filesystem, and a second filesystem server would widen access for no gain. Gemini prices are a web fetch, not an MCP, and the user's key stays out of the repo. The new files are not in the zip.
